What is HTML?

HTML (HyperText Markup Language) describes the structure and meaning of a page. It is not a programming language — there are no loops or variables. Each tag labels a piece of content so browsers, search engines and screen readers all know what they are looking at.

A minimal document needs four things: a <!DOCTYPE html> declaration, an <html> root with a lang attribute, a <head> for metadata, and a <body> for everything visible.

Why semantic tags matter

<div> means nothing. <nav> means "this is navigation". Swapping generic containers for semantic ones costs nothing and buys three things:

  1. Accessibility — screen readers can jump between landmarks.
  2. SEO — crawlers understand what the content is about.
  3. Maintainability — the markup reads like an outline.

How the web works

Typing an address and pressing Enter sets off a short chain of events:

  1. DNS lookup — the domain name is resolved to an IP address.
  2. TCP/TLS handshake — a connection is opened and, over HTTPS, encrypted.
  3. HTTP request — the browser asks the server for a resource.
  4. HTTP response — the server replies with a status code and the HTML.
  5. Rendering — the browser parses HTML into the DOM, applies CSS, runs JavaScript and paints.

Frontend vs backend

The frontend is everything running in the browser: HTML, CSS and JavaScript. The backend runs on the server: application code, databases and APIs. They meet at the HTTP request — the frontend asks, the backend answers.
