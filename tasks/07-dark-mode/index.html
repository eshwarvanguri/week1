Tokens, not rules

Colours live in CSS custom properties. Switching theme rewrites the token block; every rule below it stays untouched.

OS first

prefers-color-scheme sets the default, so first-time visitors already get the theme their device asked for.

Choice wins

A data-theme attribute on <html> overrides the OS in both directions and is saved to localStorage.

The flash problem. If the saved theme is applied by a script at the end of the body, the browser paints the light page first and then repaints dark — a visible white flash. The fix is the small inline script in <head>, which runs before anything renders.

How it works, step by step

  • :root defines the light palette as the baseline.
  • A prefers-color-scheme: dark block redefines those tokens for the OS preference.
  • A :root[data-theme="dark"] block redefines them again, so an explicit choice outranks the OS.
  • The guard :root:not([data-theme="light"]) on the media query lets someone force light on a dark OS.
  • The toggle writes data-theme and saves it; a matchMedia listener keeps following the OS until it does.

Accessibility

  • The switch is a real checkbox with role="switch" — it toggles with Space and announces its state.
  • Both palettes were checked for at least 4.5:1 contrast on body text.
  • The colour transition is disabled under prefers-reduced-motion.
